あなたはMAGI審査システムのGrok Build CLI接続担当です。審査ではなく、Grok Build自身のサブスク接続セットアップと疎通確認を実施してください。

作業場所: このリポジトリのルート（現在の作業ディレクトリ）
最初に README.md と magi/providers.py を読んでください。Codex側が全体を統合します。新しいCodexチャットや子エージェントを作らないでください。

実施すること:
1. インストール済みの公式Grok Build CLIのバージョンとhelpを確認してください。サブスクOAuthには magi.providers.grok_home() が返すアプリ専用領域を使います。標準のGrokホームから認証ファイルを読んだりコピーしたりしないでください。
2. magi.providers.preflight('grok') を実行してください。既存アダプタは専用config.tomlのauth.disable_api_key_auth=trueと子環境変数GROK_DISABLE_API_KEY_AUTH=1を設定し、grok inspect --json の loginPolicy.apiKeyAuthDisabled=true と許可された設定元を確認します。requirements.tomlはCLIが同期する署名付きキャッシュなので手編集しないでください。auth.jsonは存在だけを確認し、内容を開かないでください。doctorはトークンの有効性までは証明しない点に注意してください。
3. 専用領域にOAuth認証がなければ推論を実行せず、blockerと公式ログイン手順を報告してください。PowerShellで一時的に $env:GROK_HOME = python -c "from magi.providers import grok_home; print(grok_home())" として grok login --oauth を実行し、終了後にこのプロセスのGROK_HOMEを元に戻す手順です。ログイン操作、ブラウザでの本人認証、契約変更は担当者に任せてください。
4. 準備できていれば、magi.providers.invoke('grok', prompt, schema, work_dir, timeout=120) を使い、小さな実リクエストを1回試してください。schemaは追加キー禁止の {"provider":"grok","status":"ready"} を要求するJSON Schema、promptもこのJSONだけを返す短文にします。work_dirは setup/results/grok/ 配下の新しい空ディレクトリにしてください。これは --prompt-file、--json-schema、--toolsの空引数、--deny *、公式CLIの既定モデル、応答JSONの解析を通す確認です。モデルを明示する場合は当該サブスクのgrok modelsが示すIDを使います。このセットアップ依頼文自体を再実行させないでください。
5. 失敗したら自分のprovider部分だけを診断してください。インストール済みCLIのhelpと実際の出力に基づき、認証・専用GROK_HOME・Windowsの引数・promptファイル・スキーマ出力の問題を分けてください。APIへの切替や制限解除で通さないでください。追加の実リクエストは、判明した原因を直した確認に必要な最小回数だけにしてください。
6. 必要な修正案は setup/results/grok/proposed.patch と診断メモに保存してください。共有の magi/providers.py、README、tests、他providerのファイルは直接変更しないでください。既存の該当テストを必要に応じて実行し、模擬テストと実通信成功を区別してください。

守ること:
- シェルの複数行インラインコード、パイプ、コマンド連結を使わず、必要なPython処理はsetup/results/grok/内の.pyファイルに保存し、pythonで始まる単一コマンドで実行してください。許可のない操作を回避して実行せず、拒否された場合は報告してください。
- APIキー、OAuthトークン、資格情報ファイルの内容を読まない・コピーしない・出力しないでください。環境変数の一覧や認証ファイルのダンプは禁止です。表示にメール等が含まれる場合も結果には残さないでください。
- API従量課金、API認証、BYOK・独自エンドポイント、有料契約・サブスク変更、全体ユーザー設定の変更を使わないでください。既存アダプタのAPI認証禁止、外部設定隔離、ツール実行禁止を維持してください。
- 成果物の書込みは setup/results/grok/ のみにしてください。ただし既存アダプタが専用GROK_HOMEへ公開の隔離設定を再適用する処理は許可されています。認証ファイルの手編集は禁止です。

最後に setup/results/grok/result.json をUTF-8で保存してください:
{"provider":"grok","ready":false,"blocker":null,"commands":[],"tests":[]}
readyは既存アダプタ経由の実通信で指定JSONが返り、API課金を使っていないと確認できた場合だけtrueです。blockerは未解決事項の短い文字列またはnull、commandsは実行した秘密情報を含まないコマンド、testsは{name,kind:"live"|"mock"|"static",passed,detail}の配列にしてください。未実施テストを成功扱いしないでください。最終回答にはready、blocker、成果物の場所だけを簡潔に書いてください。
